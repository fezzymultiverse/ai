What changed

Scoped native HTTP for documented AI hosts avoids the old bridge's endpoint restriction without allowing arbitrary URLs. Exact HTTPS hosts and API paths are checked; redirects are disabled; only loopback 127.0.0.1:1337 HTTP is allowed. Inference requests time out at 18 seconds and catalogue requests at 6 seconds in the new transport. Network cancellation is best-effort: a timed-out native HTTP operation may finish independently; no result from it is shown later.

Automatic rescue defaults on when no preference exists, respects an explicitly saved OFF, keeps the selected provider unchanged, and identifies the provider/model that actually answered. Rescue is restricted to up to three of the checked anonymous services, with a 45-second scheduling budget checked before each attempt; in-flight requests may extend the total. It never sends paid-provider keys in cross-provider rescue. Original manual paid integrations were not removed. Privacy consent remains required for each provider.

Keyless model catalogues refresh before first inference and then after ten minutes; stale model selections are reconciled. Cloudflare is restricted to a small documented safe model set rather than promising all listed models are callable on your account. Existing browser-assistant keyless/Cloudflare calls now use the same provider implementation rather than a divergent copy of the routing logic. Settings model/completion probes use the same scoped transport for covered APIs.

Maps: implemented versus not implemented

Implemented in the web layer: in-chat map cards and full-screen app; up to three selectable route alternatives when returned by OSRM; Car, Walk, Bike and Taxi road profiles; Start/Stop foreground GPS navigation; current-step highlighting; turn prompts through your selected HorizonTTS voice with its existing Android fallback; follow/recenter; accuracy gating; three off-route fixes before recalculation; cooldown to prevent request storms; nearby category markers with Directions here; long-press destination pin; recent routes; locally bundled Leaflet 1.9.4 with CDN fallback.

Nearby categories: shops, food, health, fuel/garages/car repairs, charging/water/toilets/recycling and some utilities, transport/parking, mapped traffic-light locations, electronics and makerspaces. Category searches are within 2.5 km of the map centre and display up to 40 results, with caching. This is not a complete directory. Robotics uses electronics/makerspace tags, not a verified inventory of robotics shops. Arbitrary text lookup uses Photon. Public Nominatim requests were removed to avoid building a generic AI geocoder on that restricted service.

Not implemented: live traffic congestion or traffic-aware ETAs, light phases, Waze incident reports, speed enforcement, offline routing, verified bus/train journeys or schedules, all global places, background/locked-screen navigation, lane-level guidance or safety certification. Transit remains explicitly labelled nearest-stop plus road-time estimation, not a real transit itinerary. Demo/public services are rate-limited and unsuitable as a guaranteed production backend at scale.

Real live checks returned a car route, two walking alternatives and a bike route for public Cape Town coordinates. UI tests used deterministic three-route fixtures, synthetic GPS movement and a mocked speech function. They prove control flow, not real road safety or actual spoken sound. Keep Horizon visible, check location accuracy, and follow road signs.

Try after installing a rebuilt APK: “Show directions from here to [place]”, then choose a route and press Start. “Show garages near me” opens numbered map markers. Traffic-light markers indicate only mapped positions, not current colours. Turn voice can be muted or stopped independently.

RSS reading and AI summaries

The existing RSS app now has an AI digest button and Read aloud. It refreshes saved enabled feed excerpts, passes the data to the selected Horizon provider, and displays a summary plus source links. Feed contents are treated as untrusted data. The AI tools [[rss.feeds: list]] and [[rss.read: feed name or all | 15]] are registered in the chat dispatcher and shared full/lite model prompt.

This reads RSS/Atom excerpts, not arbitrary full articles or paywalled pages. Each read is limited to the first six matching enabled feeds and up to 30 items, with that partial scope stated in the result. Refresh errors and stale-cache fallback are identified. It is user-triggered, not a new scheduled/background news job. AI summaries still depend on a working provider.

Try “Read my saved RSS feeds and summarise the latest items with links”, or open RSS → AI digest. Nothing is read aloud until requested.

Integrate into your complete Android project

Keep your installed app and take an in-app backup first. Do not uninstall or clear app storage. Extract this ZIP separately. The new helper changes only the listed repaired web files and backs up existing versions; it does not replace your complete Android folder or regenerate the app.

python3 scripts/apply_repair_v62.py /path/to/your/complete/horizon
# Review the dry run, then apply:
python3 scripts/apply_repair_v62.py /path/to/your/complete/horizon --apply
# In the COMPLETE project, use its existing dependencies and build pipeline:
npx cap sync android
# Then run your existing Gradle build/signing job.

The target must contain package.json and android/. The helper honors Capacitor's configured webDir, backs up originals under .horizon-backups/, and enables CapacitorHttp in JSON configuration while preserving other plugin settings. For TS/JS configuration, it prints a check rather than rewriting it: plugins: { CapacitorHttp: { enabled: true } }. Preserve all existing Horizon native plugins, Location permission, the app's manifest and signing identity. The built-in CapacitorHttp plugin must be supported by your installed Capacitor native runtime; this was mocked, not compiled here.

G4F Local needs a separately running server on the phone. If Android blocks it, add a loopback-only network-security exception in your complete project. Do not disable TLS verification or globally permit cleartext traffic. No unknown external relay was added as a workaround.

After rebuilding: test Kilo Auto Free or OVH GPT-OSS first; verify Settings' free/keyless fallback switch (an explicitly saved OFF remains off); then test Cloudflare with your own account credentials; check RSS; finally do a walking-only GPS/TTS test in a safe place. No live driving tests have been performed.
