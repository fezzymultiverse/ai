HORIZON V1.93.0 — ANDROID-ONLY VOICE STUDIO

WHAT IS INCLUDED
Updated editable source project, a source patch, validation JSON, test logs, native build log,
dependency audit output, a before/after desktop benchmark and a voice-panel screenshot.
This is a source delivery, not a production-signed APK. No signing secrets were added or changed.

OPEN THE CONTROLS
Settings > Personalisation > Voice. Select your Android voice, choose a character preset,
then tap Test. Get more Android voices opens the phone's TTS settings.
Neutral / Natural narrator is the fastest path. Reset to neutral clears all effects.

TEN SOUND CONTROLS
1 Speed; 2 Pitch; 3 Bass (180 Hz); 4 Presence (1.5 kHz); 5 Treble (5 kHz);
6 Envelope compression; 7 Damped-comb room reverb; 8 Feedback echo (190 ms);
9 Robot ring modulation (73 Hz); 10 Experimental chromatic pitch-snap.

TEN CHARACTER PRESETS
Natural narrator, Heroic captain, Shadow villain, Space robot, Tiny sprite,
Stone giant, Ancient wizard, Neon android, Radio announcer, Echo phantom.
These shape your selected Android voice; they do not clone actors or named characters.
The Custom option is a separate editing state, not an eleventh preset.

ANDROID-ONLY ARCHITECTURE
Removed cloud TTS providers and their configuration UI, neural speech pack downloads,
Kitten/Kokoro/Piper synthesis, Sherpa/ONNX plugin/payload bundling, and the now-unused
native archive dependency. Voice-note recording/transcription and AI chat providers remain.
Android's default TextToSpeech service is the sole synthesis source. Android controls its
installed engine and voice data; Horizon does not select another provider or fallback engine.
An online Android voice can still use its Android service's network. Download voice data
and choose an offline Android voice to work offline.

Neutral speech uses direct Android TTS. Effects use Android synthesizeToFile into private
temporary WAV files, background Java DSP, and native MediaPlayer. There is no base64 PCM
round-trip through JavaScript and no WebAudio fallback. Speed/pitch are applied once by
Android. EQ uses RBJ low/high shelves and a presence bell; processing includes an envelope
compressor, damped-comb room, feedback echo, ring modulation, peak limiting and edge fades.
Pitch-snap uses autocorrelation, interpolated pitch estimation and pitch-synchronous
windowed overlap-add. A 225 Hz fixture measured 220.007 Hz when targeting A3 (220 Hz).
It remains experimental: speech, noisy/unvoiced frames and high-pitched voices can sound
artificial. It is not professional singing correction or a formant-controlled voice clone.

PERFORMANCE CHANGES
- TTS JavaScript reduced from 71,674 to 15,044 bytes (79.0% smaller).
- No bundled neural model, model unpacking, neural inference or speech pack download UI.
- Android TTS initializes lazily and releases its engine after idle time.
- DSP work is bounded and kept off the main UI thread; stale jobs and temp files are cleaned.
- Voice lists are cached and concurrent enumeration coalesces.
- Idle waveform callbacks are reduced; periodic whole-page add-on sweeps were removed.
- Voice-note discovery inspects added DOM subtrees instead of scanning the whole document
  after every stream/UI mutation; hidden terminal rain does not spin a per-frame callback.
- Hidden native browser views are paused; new tabs have an eight-view memory limit.
No chat storage, provider configuration, music content, contacts, Termux data, layout theme
or existing attachment/recording data is intentionally removed.

MEASUREMENTS — NO INVENTED SPEEDUP
Final desktop medians: original load 956 ms; modified load 984 ms.
DOM ready: original 951 ms; modified 977 ms.
This did not demonstrate faster startup. Test scope: local Chromium, 412x915, 4x CPU
throttle, external services blocked, five fresh contexts per build in alternating order.
An earlier run overlapped a native build; its raw results are included separately, not
used to claim a speedup. These are not measurements of Android scrolling, keyboard input,
API latency, real phone memory, startup or battery. Removed work is verified in source;
a device-level speed claim still needs profiling on the target phone.

SECURITY / RELIABILITY FIXES
- Browser programmatic open/navigate and download handlers now reject non-HTTP(S) URLs;
  embedded URL credentials are refused. This closes paths around page-navigation checks.
- File/content access and file-origin cross-origin privileges are explicitly disabled.
  Safe Browsing is enabled where available; certificate errors remain fail-closed.
- Exported alarm boot receiver only accepts its intended protected system actions.
- Removed remote voice model loading and archive extraction attack surface.
- Native speech text, queue depth, PCM encoding, RIFF chunk lengths, size, duration,
  cancellation, callback IDs and processing lifetimes are bounded/checked.
- Fast pause/resume and speech replacement races have regression coverage.
- npm advisories: 5 affected package entries before, 0 after. Patched tar/glob/minimatch
  are pinned, with a guarded Capacitor 6 / tar 7 import compatibility shim. Clean npm ci
  and Capacitor sync were tested; shim is automatically applied by postinstall.
This is a scoped code review and hardening pass, not a complete penetration test or a
claim that the project is free of every vulnerability/backdoor. Existing API-key/vault
storage and OS backup policy have not been redesigned. Never treat unknown AI-generated
commands or web content as trusted instructions merely because the app has an app lock.

UPGRADE BEHAVIOUR
Application identity and the V1.93.0 version label are preserved. A one-time WebView cache
migration prevents stale same-version assets. Only old horizon_voice, horizon_packs and
sherpa model directories are cleaned, off the UI thread; other user storage is untouched.
Old Cloud TTS credentials/settings are removed from the TTS-specific localStorage keys;
chat-provider keys and unrelated preferences are not erased.
Generated android/ trees also remove only the old neural voice source/model/native libs.

BUILD / RELEASE
Use your existing GitHub Actions workflow and existing signing secrets. It now tests the
new DSP/UI and verifies that removed neural payloads are absent. No model download is needed.
Local standard flow (Node 20+, JDK 17, Android SDK 34):
  npm ci
  npm test
  npm run test:voice-dsp
  npx cap add android                         # only for a fresh source checkout
  bash scripts/apply-android.sh
  bash scripts/set-version.sh <unique-version-code>
  npx cap sync android
  cd android && ./gradlew assembleDebug
For the complete browser suites, install Chromium with npx playwright install --with-deps chromium,
then run npm run test:browser and npm run test:voice-browser.
For a small-memory build host use --max-workers=1, -Pkotlin.compiler.execution.strategy=in-process
and suitable Gradle JVM heap settings; the final sandbox build succeeded with a 640 MiB heap.
Use your existing release signing key to update the installed app. Do not uninstall an existing
installation just to work around a signing mismatch; that can erase app data. Back up important
data through the app's own existing export first, and keep any exported secrets private.
