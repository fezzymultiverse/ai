HORIZON V1.99.133 - PLAYLISTS: THE AI MAKES THEM, PLAYS THEM, AND SAVES THEM INTO FOLDERS

Why (Fezzy's report): the playlist tool existed since V1.99.130, but the AI was not using it well. Two older prompt lines (index.html "PLAYLISTS:" and horizon_toolpolicy.js, three places) still told the AI to build playlists by hand with yt.play + yt.queue, which contradicted the KEYLESS STUDIO tool and made it ask / improvise. Also every download landed flat in Download/ with no folder.

Changed
- Folders: playlist downloads now save into Download/Horizon/<playlist name>/ with numbered files (01 - Artist - Song, 02 - ...), in playlist order. Plumbing: Studio.download -> host.get(q, {folder, prefix}) -> ytGetTool -> ytSaveAndWait -> queueDownload (d.folder, d.prefix) -> saveFile -> HorizonAI.saveMedia({folder}); Kotlin builds RELATIVE_PATH = Download/<folder> (each part cleaned, max 2 levels). Normal single-song yt.get downloads are unchanged (no folder = Download/ as before).
- Play first: playlist.create with play:true AND download:true now starts listening first (track 1 plays, rest queue), THEN saves the songs. Before, it waited for every download before any music.
- The AI takes the lead: new KEYLESS STUDIO prompt tells it to choose 8-15 real tracks itself, name the playlist, make ONE playlist.create call, never ask which songs, and to map "save / keep / download / offline / in Music / folder" to download:true. Replaced the conflicting hand-queue advice in index.html and horizon_toolpolicy.js.
- New tools: [[playlist.add: {"name","tracks":[...],"download":false}]] (appends, skips duplicates, max 30) and [[playlist.delete: name]] (removes the list only, never saved files).
- The result text now names the folder so the AI can tell you where the songs are.

Files: www/horizon_studio.js, www/index.html, www/horizon_toolpolicy.js, www/horizon_about.js (version), android-native/app/HorizonAIPlugin.kt, tests/playlist-folders-v133.test.cjs (new, 6 tests), tests/studio-v129.test.cjs (cache-bust string), package.json, package-lock.json.

Checked: node --check on every www/*.js and all 4 inline scripts of index.html; new tests (mocked host: folder + numbering, play-before-download order, add/delete, tag parsing, prompt wiring, native wiring) pass; studio and worker-guard tests pass.
NOT checked: no APK built, the Kotlin change is NOT compiled, nothing run on a phone. Needs a rebuilt APK for folders (the old APK ignores the folder and saves flat into Download/, nothing breaks). I did not verify that Music's scan includes sub-folders of Download, so downloaded songs may need the Music tab's Scan, or may only show if that scan covers Download/Horizon. Real YouTube downloads and streaming were not exercised. Whether the AI follows the new prompt depends on the provider and model; small models may still ignore tags.
