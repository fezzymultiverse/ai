HORIZON V1.99.149 - HORIZON NOTIFICATIONS STAY (Kotlin)
Why they disappeared (found in the code, two causes):
1. Finished-reply alerts were built with setAutoCancel(true): one tap and Android removed them.
2. Every reply used one id per chat (5100 + chat hash), so a newer reply in the same chat REPLACED the older one.
Fixes:
- HorizonNotify.alert(): setAutoCancel(false) on the rich banner and on the plain fallback. A tap opens Horizon and the notification stays. Swiping it away still works (it is NOT ongoing).
- HorizonAIPlugin.publishReply(): each finished reply gets its own id (100000 + a counter, ring of 300) so replies stack instead of erasing each other. The "Horizon is thinking" status stays on the chat id and is still cancelled before the answer, so the inline-reply spinner does not linger.
- HorizonCheckinPlugin: the proactive check-in notification no longer auto-cancels on tap.
- HorizonDaemonPlugin alerts use the same alert(), so they also stay now.
Not changed: WhatsApp's own notifications. When the WhatsApp auto-reply fires WhatsApp's Reply button, WhatsApp itself updates or removes its notification; Horizon cannot stop that.
NOT CHECKED: no Kotlin compile (no toolchain here), no APK build, no phone run. Android caps an app at about 50 notifications.
Files: android-native/app/HorizonNotify.kt, HorizonAIPlugin.kt, HorizonCheckinPlugin.kt
