HORIZON V1.99.136 - EYES 2 (A MODEL THAT CANNOT SEE CAN NOW LOOK, ZOOM AND MEASURE)

Problem: V1.99.135 gave a text-only model (ch.at, Groq text models, most free models) ONE description of a picture. A description is a blind person asking "what colour is yellow": the model could not look again, could not zoom, every colour was only a word, and the UI Lens never even took a screenshot for a model that cannot see (it sent the UI map only).

What is new
1. REAL PIXEL FACTS (www/horizon_eyes.js). The app measures the picture itself on a canvas: size, tone, the exact palette in hex with percentages, and the dominant colour of each cell of a 3x3 grid. No vision model is involved, so these numbers cannot be invented. They ride along with the description, labelled as measured.
2. FOLLOW-UP QUESTIONS  [[see.ask: n | question]]  The chat model asks, a vision model looks at the REAL picture again and answers just that. As often as needed (4 tool rounds, 3 tags per round).
3. ZOOM  [[see.zoom: n | region | question]]  The app crops and enlarges the region (top-left ... bottom-right, top/bottom/left/right half, or x,y,w,h in %), so small text becomes readable. The exact colours of that region are measured from the ORIGINAL pixels and attached.
4. EXACT COLOUR  [[see.color: n | x%,y%]]  The measured pixel (5x5 patch average): hex, rgb, name. Several points with ; . Never a vision model, never a guess.
5. THE APP'S OWN SCREEN  [[see.ui]] = the live UI map (real element names, sizes, colours, contrast ratios, auto-found problems) on demand, not only when the message matches the Lens wording. [[see.shot]] = a fresh screenshot (Vault, keys and password fields blurred), registered as a picture, read and measured, then open to see.ask / see.zoom / see.color.
6. LENS FIX. Lens used to capture the screenshot only when the chat model could already see. Now a text-only model gets it too, read by Horizon Eyes. ("Lens: looked at the app" shows the full UI map and a real screenshot.)
7. GROQ VISION. A Llama 4 / Scout / Maverick / vision model selected on Groq now counts as a picture reader (canSeeImages + Eyes sources). Horizon never swaps your chosen model: choose a vision model on Groq to add it.
8. CLEANER READS. A vision call now gets a tiny "image reader" system prompt instead of the whole Horizon persona and tool contract (it used to be asked to read a picture while holding the full prompt). It is set only for the synchronous call and cleared at once, so it cannot leak into another chat. The 45 s reader timeout is cleared when the read finishes.
9. SETTINGS. Lens window (Apps menu, Lens) has a new section HORIZON EYES: On/Off and "Reader to try first" (Auto or any ready provider).

Pictures live in memory for the session only (last 8 per chat), never in storage. The prompt block only offers the picture tools to a model that cannot see; a model that can see gets only [[see.ui]]. Off switches: localStorage horizon_eyes = '0' (all picture reading), horizon_eyes_tools = '0' (the see.* tags). Prefer a reader: horizon_eyes_first = provider id.

Honest limits
- A text-only model still never receives pixels. This is vision by interrogation plus measurement; it is only as good as the vision reader on the other end and it can still miss small text, which is what see.zoom is for.
- see.shot and the screenshot half of Lens need the Android build with the HorizonLens plugin (already in android-native). In a browser the UI map still works.
- Whether Pollinations' current model really reads images was not tested (last in the reader order).
- NOT checked: no APK build, no real provider call, no device run. Checked: unit tests with mocks, and a real-Chromium run (tests/eyes-v136.browser.cjs) that measured exact colours from real canvas pixels, cropped a region, and rendered the Lens Eyes section with zero page errors.
