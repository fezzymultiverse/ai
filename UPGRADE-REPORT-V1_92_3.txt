Horizon V1.92.3 - cleanup release (folds in V1.92.0 to V1.92.2)
Source patch on Horizon V1.92.0

CHANGES IN THIS RELEASE
1. Version drift fixed. The V1.92.0 source already contained V1.92.1 (long chats open on the newest 40 messages),
   V1.92.2 (live download progress card) and V1.92.3 (one-line tool descriptions) work, but package.json, the ?v= cache
   tags, About, the release migration and the changelog all still said 1.92.0, and package-lock.json said 1.91.0.
   Every stamp now reads 1.92.3 and the About changelog has entries for V1.92.1, V1.92.2 and V1.92.3.
2. New scripts/bump-version.sh: "bash scripts/bump-version.sh 1.92.4" stamps every version location, and
   "bash scripts/bump-version.sh --check" lists them and exits 1 if any disagree (it also checks the newest changelog entry).
3. Removed the LeakCanary stub: HorizonCanary.kt, the /canary slash menu, canaryStatus / canarySet / canaryOpen in
   HorizonAIPlugin.kt, HorizonCanary.init in MainActivity.java, its check and file entry in apply-android.sh and its name in
   the APK class check in build-apk.yml.
4. Removed Snooze leftovers: the #snoozeBtn lookups in index.html and horizon_screen.js (the Screen tool no longer shows a
   permanent "Snooze off" chip) and the stale snooze comments in index.html and horizon_hdr2.js.
5. Removed unused native calls HorizonAlarm.nextRing, HorizonAlarm.clearSong and HorizonBrowser.closeAll (no JS or Java caller).
6. Removed 19 CSS declarations that a later rule with the same selector always overrode. A before/after check of the
   final value for every selector and property shows 0 differences. Fallback pairs (100vh then 100dvh and similar) were kept.
7. Removed stale files: UPGRADE-REPORT.txt (identical to the V1.91.0 report), UPGRADE-REPORT-V1_91_0.txt,
   UPGRADE-REPORT-V1_92_0.txt (folded in here) and the validation/ folder (V1.88.0 results). validation/ is now in
   .gitignore and tests/performance.compare.cjs creates it when it needs it.
8. README: first banner updated, stale V1.90.0 banner and the validation/ note removed.
9. Stale comment in horizon_ind.js (pointed at a stylesheet that no longer exists) corrected.

KEPT ON PURPOSE
- PERFORMANCE-PLAN.txt: its Phase 2 real-phone checks were never run.
- The old About changelog entries and the README history: they are history, not dead code.

V1.92.0 NOTES (unchanged)
- WhatsApp silent background send toggle (default OFF): no dialog, WhatsApp never opens. 10 sends/hour cap.
- Reply actions survive notification dismissal; stale ones fail cleanly and report "Nothing was sent".
- No live reply action: Horizon posts a tap-to-send notification and the AI is told to inform you.
- "AI sees new messages and reads without asking" toggle: recent previews go into the AI context.
- Needs: Notification access, Allow confirmed replies ON, contact must have messaged since Horizon connected.
- Not integrated: WhatsApp Business Cloud API (needs Meta token + phone number ID + a webhook server).
- Colors: light/neon greens now use --neon (#bf5fff) on dark pills; light themes use --neon-deep. PDF export colors untouched.
- Speed: chat save debounced (400 ms, flushed on hide/backup); Lite mode (auto on <=4 GB RAM or <=6 cores) removes
  shadows/blur. Set localStorage hzLite=0 to turn Lite off.
- Terminal: the AI is told when Termux is installed but off and how to switch it on. Defaults are still OFF.

TESTED: node --check on every JS file and the inline script; bash -n on every script and shellcheck on bump-version.sh
(clean); node unit tests 105/105; tests/browser.smoke.cjs passes (no uncaught errors, no missing assets, unique IDs);
a headless-Chromium check that the slash menu has no /canary, the Tools menu paints its check chips and 12 descriptions
with no errors and no Snooze chip; CSS brace balance and a before/after cascade comparison (0 differences);
bump-version.sh --check (all stamps agree); repeat dead-code scans (no orphan scripts, no unreferenced CSS classes,
no unused inline functions).
NOT TESTED: Kotlin and Java compile, APK build, on-device behaviour, real startup time.
Rebuild through the GitHub workflow, then check: /notif still works, the Tools menu opens, a download shows its card,
a long chat opens on the newest messages.
