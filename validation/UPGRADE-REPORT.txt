STATUS / IMPORTANT BOUNDARIES
Source changes are implemented, regression-tested and Java/Kotlin-compiled.
There was no Android device/emulator session, authenticated provider inference,
actual Termux execution, WhatsApp message send, notification delivery or audible
voice playback in this environment. Do not treat compilation or mocks as those tests.

PHASE 1 — ONE STANDALONE TERMINAL OWNER
Place: standalone Terminal > Controls. Mode: manual Android sh remains unchanged;
Termux is an explicit, separate native bridge inside Controls.
- Moved the existing permission subtree outside Settings; no cloned controls,
  duplicate state or replacement permission handlers.
- Device / WhatsApp / Termux & AI section navigation in the scrollable control hub.
- Preserved old internal permission links by redirecting them to Terminal Controls.
- Added Allow AI commands, default OFF. AI tool and AI downloader paths carry an
  origin flag, checked natively; every Termux execution still needs native approval.
- Native execution rechecks lock state and permissions after approval.
- Existing Terminal AI dock is hidden while Controls is visible, not destroyed.
- No unrelated provider, theme or music-mode controls were moved/reimplemented.

PHASE 2 — CONTACTS AND BACKGROUND WHATSAPP
Place: Contacts tile at the bottom-right of the right-panel Apps grid; also Apps.
Story: search device names locally, choose an exact phone-row identity, then use
its chat card to send manually or explicitly share that selected recipient with AI.
- Android READ_CONTACTS permission and 50-row paginated local search.
- Native exact-name resolution refuses ambiguous names/multiple phone numbers.
  Phone URI matches use full normalized digits, never Android loose suffix matching.
- Background send uses an ACTIVE, direct-chat notification's RemoteInput action.
  Group notifications and missing/expired actions are refused. Source, lock and
  permission gates are checked again when Send is approved.
- Contact send has NO compose/open-WhatsApp fallback. Android 12+ Activity reply
  actions are explicitly refused. Submitted is never represented as delivered.
- Existing explicit whatsapp.compose remains a separately labelled, confirmed draft
  for backward compatibility. Only a deliberate compose request opens WhatsApp.
- Selected recipient is not added to AI context until Use contact in AI chat;
  selection clears on chat navigation, group selection, new chat and app lock.
- Contacts/inbox dialogs carry data-hz-private to exclude automatic UI Lens text.
- Existing native notification listener and WhatsApp icon/sender alerts retained;
  lock-screen content remains redacted, with seven-day/300-message retention.
LIMIT: Arbitrary new personal WhatsApp chats CANNOT be silently sent through this
notification-reply integration. No matching active reply action means an explicit
error, not a fake success or an app launch. An official Business Cloud API setup
would be a separate integration. Muted/hidden notifications and full history are
not available here. Android/OEM background restrictions still apply.

PHASE 3 — VOICE, KEYS AND PROVIDERS
Offline root causes addressed:
1) The original download executor could release/replace a model while the synthesis
   executor used it. Installation swaps now run on the same serial model worker,
   with a previous-pack backup and rollback; concurrent downloads are rejected.
2) Saved downloaded-voice identity could be resolved against stale JS pack cache.
   Installed packs are refreshed before saved speaker selection; completed downloads
   select their own offline voice and invalidate old loader state.
3) The build followed newest sherpa-onnx. Newer APIs remove the espeak behavior
   this app's Kitten/Piper/Kokoro packs use. Default is pinned to v1.12.14; an
   incompatible explicit override fails loudly instead of silently changing speech.
- Validate speaker bounds and audio metadata before synthesis/publishing ready state.
- Native WAV playback, fallback, stop/pause/resume and group voice selection preserved.
- AQ./Aq. key bytes remain intact; added dotenv/PowerShell/Google environment aliases
  and Gronkrouter spelling alias to the existing GonkaRouter provider id.
- New-style keys are also redacted by existing Vault/shell/UI text scrubbers.
- Existing API base URLs retained where verified; no speculative host substitution.

Live probes, unauthenticated (not successful chat/inference proof):
  GET https://api.gonkarouter.io/v1/models -> 401
  POST https://api.gonkarouter.io/v1/messages -> 401
  GET https://api.anyapi.ai/v1/models -> 401
  POST https://api.anyapi.ai/v1/chat/completions -> 401
  GET https://api.routeway.ai/v1/models -> 200
  POST https://api.routeway.ai/v1/chat/completions -> 403
See validation/provider-endpoints.json for exact responses and timing. In particular,
Routeway's chat URL was blocked by Cloudflare from this environment. GonkaRouter and
AnyAPI authenticated calls still require the user's valid key and live eligibility.

Optional Cloud TTS:
- Added Google Cloud Standard en-US-Standard-C via the supported synthesize endpoint,
  with its own restricted key (never borrows Gemini keys), native WAV playback and
  offline fallback.
- Published Standard voice allowance: 4 million characters/month. Google requires
  billing and may charge beyond its allowance. This is an OPTIONAL FREE TIER,
  not an unlimited/keyless/no-billing service.
- Local UTC-month cap reserves characters before the HTTP request and fails closed
  if usage cannot be persisted. It cannot account for other apps/devices, provider
  accounting windows, cleared storage or concurrent app instances. Set provider-side
  quotas. No real Cloud TTS/audio request was made in validation; fixture audio only.

PHASE 4 — TARGETED LAYOUT / KEYBOARD WORK
- Removed obsolete cached old-header reload switching, unused drawer icon builders
  and old drawer/scrim/drag CSS; preserved header modules needed by the current UI.
- Did not wipe user caches, keys, chats, settings or media libraries.
- Preserved the existing composition-safe autosize and late-IME-event no-blur guard.
- One document-wide editor-focus signal covers chat, Contacts and Terminal editors.
- Terminal rain/HUD and header speaker decoration back off while editing/IME motion.
- Removed a redundant delayed viewport re-fit; native/visualViewport measurement

- This is not a physical-device latency benchmark or proof all stutter is gone.
