HORIZON V1.99.130 - AI SAVES PLAYLISTS, MUSIC AND PODCASTS WHEN ASKED

What changed
- playlist.create with "download":true saves the playlist, then downloads every song one by one through the existing verified saver (yt.get), rescans Music, and returns a tracklist (SAVED / FAILED / NOT SAVED per song) for the AI to send you. New tool: playlist.download: name.
- studio.music with "save":true makes the WAV instrumental and saves it to Downloads with no taps.
- studio.podcast with "save":true records the AI-written script with the Microsoft Edge voice and saves an MP3 to Downloads. Needs internet and the new native method (see below).
- File manager prompt: the AI may only say "blocked" for OPERATION_DENIED or Android/data and Android/obb. OUT_OF_SCOPE now means: declare scope with the exact path and retry once.
- About cards updated to match.

Files: www/horizon_studio.js, www/horizon_edge_tts.js, www/horizon_files.js, www/horizon_about.js, www/index.html (Studio host: get + rescan), android-native/com/festers/horizon/edge/HorizonEdgeVoicePlugin.kt (new renderMp3).

Checked: node --check on every changed JS file and all inline scripts of index.html; Studio logic unit-run with mocks (playlist download, tracklist text, partial failure, save flags).
NOT checked: no APK built, Kotlin NOT compiled, nothing tested on a phone. Real YouTube downloads, Edge synthesis and the file-manager prompt change are unverified. Podcast MP3 needs a rebuilt APK with the new Kotlin (the old APK shows a clear "no render support" error). Podcast limit 30000 characters, MP3 returned as base64 so very long episodes use a lot of memory.
Songs saved by yt.get follow the app's existing download location; whether they appear in the Music tab depends on that location being in the Music scan. Podcast and instrumental files go to Downloads.

Addendum: playlist.create also accepts "play":true (create, then start track 1 and queue the rest; combine with "download":true to save too).
Addendum 2: removed the "Open Keyless Studio & Playlists" button from About. The AI now does the work from chat; the Studio window still opens only when the AI uses studio.open.
Addendum 3: phone calls. dial() no longer asks to make Horizon the default phone app and callResult no longer requires it. The call is placed with TelecomManager.placeCall through the user's own default phone app and the Calling Card shows "Call placed in your phone app" (no fake live state, no 30 s failure). If Horizon IS the default phone app, the old live card with Mute/Speaker/End still works. Needs the Phone permission. Files: HorizonContactsPlugin.java, www/horizon_contacts.js. Java not compiled, not tested on a phone.
Addendum 4: "play my just-downloaded song" fix (from the Juice WRLD screenshots).
- Cause: the library was stale (new download not listed) and play accepted a match missing one of four words, so it played "Murder Scene _LABEL MIX_" and then that stale entry failed with "It may have moved".
- music.play / music.queue now need EVERY word to match; if nothing matches the app rescans once and retries; if still nothing it returns NOT FOUND EXACTLY with the closest songs and plays nothing. music.search also rescans once.
- Music prompt: rescan after a download, never play a merely close song, say "playing" only when the result starts with "Playing:".
- Chat shortcut: a miss falls back to YouTube as before, except when the message says "downloaded", then the AI gets the not-found result and asks.
Files: www/horizon_music.js, www/index.html. find() logic unit-run with mocks; syntax checked. Not tested on a phone. Whether the rescan sees the download folder depends on the existing scan scope.
Addendum 5 (real cause of "plays a different song than the mix I downloaded"): the library view hides files Android does not flag as music (t.music false), and the AI's music.search / music.play / music.queue only searched that visible list, so a downloaded mix was invisible to it. The AI tools now search ALL scanned audio (find(..., everything=true)); the on-screen library filter and the "All audio" switch are unchanged. Mock test: before, the mix was not found; after, it is. File: www/horizon_music.js. Not tested on a phone.
