HORIZON V1.99.132 - FILE MOVES WORK AGAIN + HORIZON WORKER NEURON GUARD

Fixed
- Apply on an AI file plan failed on every move with "PERMISSION_DENIED: getFileStore". Cause: HorizonFilesPlugin.java called Files.getFileStore() before each move and each undo-restore. Android does not let an app read the mount table, so that call throws AccessDeniedException, which Horizon reported as a permission error. The File access switch was never the problem.
  Now: sameVolume() compares device ids with android.system.Os.stat. If stat itself fails it answers true, and the kernel RENAME_NOREPLACE call (HorizonFilesState.renameOnly) still returns EXDEV for a real cross-volume move, which maps to CROSS_VOLUME. Nothing unsafe becomes possible, there is still no copy fallback.
  Files: android-native/app/HorizonFilesPlugin.java.
  Moving everything in Downloads works the same way: pick the Download folder with Choose folder in Permissions, then ask the AI. A plan can hold up to 2000 operations.

- Horizon Worker burned the 10,000 neuron daily allowance in about 2 messages. What the code does, measured from this source:
  1. One question can be up to 5 model calls (MAX_TOOL_ROUNDS = 4 tool rounds), and every call re-sends the system prompt plus the whole history.
  2. Only models whose name matches 1b-8b got the short prompt. llama-3.3-70b and the 32B models got the full prompt (tool contract alone is about 7.7k characters, the whole prompt is several times that).
  3. Output cap was 4096 tokens, 8000 in PDF/document mode, and the reasoning models spend all of it thinking.
  Cloudflare's published rates (neurons per million tokens, input / output): llama-3.1-8b 13,778 / 26,128; llama-3.3-70b-fast 26,668 / 204,805; qwq-32b 60,000 / 90,909; deepseek-r1-distill-qwen-32b 45,170 / 443,756. Worst case for ONE call of the r1 distill with an 8k-token prompt is about 2,180 neurons, so 5 rounds is more than the whole day.
  Now (all in www/index.html, Horizon Worker only, the existing Cloudflare provider is untouched):
  - Neuron guard: every call is priced before sending (prompt tokens x input rate + the full output cap x output rate). If that worst case could pass what is left of today's 10,000, the call is refused with a plain message and NOTHING is sent. The counter is kept per UTC day (resets 00:00 UTC = 02:00 South Africa) in localStorage key horizon_hzw_neurons, and charges the real prompt/completion token counts from the Worker's usage field when it returns them, otherwise an estimate. A timeout or Stop is charged at the worst case because the Worker keeps running and is billed.
  - The Worker always gets the short prompt (isLiteTarget), not only 1b-8b models.
  - Output cap 4096 -> 2048 (8000 in document mode is unchanged and is priced by the guard).
  - The provider card now shows how many neurons Horizon has counted today and how many are left (window.HorizonWorkerBudget).
