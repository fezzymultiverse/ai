# V1.99.101 - Radio on the shared screen + AI LINK check

Changed: NEW www/horizon_onair.js, www/horizon_radio.js (added spectrum(), nothing existing changed), www/horizon_viz.js, www/horizon_rpmedia.js, www/horizon_unit.js (one line), www/horizon_layout.css (appended), www/index.html (script tag + cache params), version in package.json, scaffold/package.json, horizon_release.js, horizon_about.js (+ changelog), horizon_model_inventory.js, NEW tests/onair-v101.browser.cjs, version asserts in tests/ground-v99.test.cjs.

1. Radio now plays on the player's screen (Widgets panel, MUSIC face). When a station starts, the unit stays on the shared screen instead of flipping to the separate dial. The RADIO tab is still the tuner and station list.
2. Waveform: the shared waveform runs while a station is on air. With a station that allows signal analysis the bars follow the real stream and the tag reads LIVE WAVE. Otherwise the bars use the same clock-driven motion as music and the tag reads SIM WAVE. A tag over the waveform shows ON AIR, the station and a STOP button (same radio.stop the AI uses).
3. Lyrics card: while radio plays, the slot shows an ON AIR card (station, frequency, country, tags) and says live radio has no lyrics. No lyrics are invented. If the lyrics box opens for a song, it takes the slot back.
4. FIX found while doing this: in V1.99.100 the shared waveform never animated in the Widgets panel, because horizon_viz.js only ran when the RIGHT panel was open. It now follows whichever panel the card is in. Reproduced before the fix (0 pixels painted), passes after.
5. The idle screensaver steps aside while radio is on air (horizon_rpmedia.js counts radio as live).
6. AI LINK log: checked in real Chromium against the real tool paths (HorizonDash.run for radio.*, HorizonMusic.run with the provider argument for music.*). Both engines get hooked, successes show a tick, errors show red, the provider argument still reaches the music engine. NOT checked with a live model making the calls.
7. Version bumped to 1.99.101 everywhere it lives, with a changelog entry for V1.99.100 and V1.99.101. package-lock.json is still at 1.99.87 (it was already stale; not touched).
8. NO APK NATIVE CHANGES: web assets only (rebuild or sync www).
9. Tests: tests/onair-v101.browser.cjs, 19 checks, all pass against local test streams (a CORS one and a no-CORS one). Not tested on a phone, not tested against real radio-browser.info stations.

10. FIX (layout void): in the Widgets panel the 6 app tiles floated right under the media unit with an empty gap below them (the earlier margin-top:auto lost to a later rule). Now the tiles sit at the very bottom and the media screen takes the spare height. Measured in headless Chromium at 360x800, 393x852, 412x915: tiles end 14px above the bottom edge, 12px gap under the media unit, both MUSIC and RADIO faces, no scrolling. At 360x640 the panel scrolls and the tiles are the last item (no overlap). Appended to horizon_layout.css only. Not checked on a phone.
