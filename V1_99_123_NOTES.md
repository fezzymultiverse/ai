# V1.99.123 - File manager PROTECTED_PATH false block

**Symptom:** every file tool (`files.scope`, list, move) failed with `PROTECTED_PATH`, even for `/storage/emulated/0/MyDocuments/IMAGES` with File access on.

**Cause:** `HorizonFilesState.protect()` fails closed on negative wording it cannot parse. The word "without" in "move it back without Termux" tripped it. It describes the method, not a folder, so it was never a real exclusion. The AI then blamed Android security.

**Fix (one Java file):**
- New `METHOD_PATTERNS`: "without / don't / do not / never + use, using, need, run, rely, require" and "without Termux, root, sudo, adb, PC, computer, internet, app, script, command, terminal, AI" are ignored by the ambiguity guard.
- Real exclusions ("leave X alone", "except X", "don't touch X") parse exactly as before. Unreadable negatives such as "not the important ones" still fail closed.
- The error now says "NOT a protected folder", names the offending word, and tells the AI how to retry.
- New test: `tests/files-v123-method-words.test.cjs` (5 pass). `files-v114` and `requested-repair` suites: 21 pass.

**Not verified:** no Java compiler in the build sandbox, so this needs a Gradle/GitHub Actions rebuild. Not tested on a device.

**Still strict (unchanged):** bare "not", "skip", "avoid", "ignore" outside a parsed clause still block. Say if you want them relaxed.
