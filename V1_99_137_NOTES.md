HORIZON V1.99.137 - WHATSAPP AUTO-REPLY (NO META, NO TWILIO, NO SERVER)

Problem: Fezzy's Facebook is suspended, so a Meta developer app (WhatsApp Cloud API) is out. Twilio's trial is a one-off and its sandbox session expires every 3 days. Baileys needs Node and cannot run inside the Capacitor app.

What is new
1. WHATSAPP AUTO-REPLY (Settings, the card under Daemon: "WhatsApp auto-reply"). With the switch on, Horizon answers WhatsApp by itself, screen off, WhatsApp never opens.
   How: HorizonNotificationListener now forwards each posted WhatsApp notification (com.whatsapp, com.whatsapp.w4b) to HorizonWaBotPlugin.kt. It reads the sender and message from the notification's MessagingStyle, asks the AI you selected (native HTTP, same provider rules and sealed key handling as the check-ins, partial wake lock for up to 90 s) and fires WhatsApp's own inline Reply action (RemoteInput) with the answer.
2. SAFE BY DEFAULT. Separate consent dialog (distinct from "Read notifications with AI"). Mode "Only the chats I list" (name as WhatsApp shows it, or phone number); "Every one-to-one chat" asks for a second confirmation. Groups, calls, group summaries and your own messages are never answered. STOP / START from the other person pauses / resumes replies for that chat. 4 s cooldown per chat, a per-chat hourly cap (default 20) and a global cap of 80 an hour, so two bots can never loop. Each message is answered once (dedupe).
3. THE AI CAN SEE THE MESSAGES. Everything it saw and answered (listed chats only) goes into a Keystore-sealed log on the phone (last 60). The card shows it (Refresh / Clear). A private AI chat turn also receives the latest rows as an UNTRUSTED DATA block; People chats never do, and it is memory-only, cleared when the turn ends.
4. Optional reply prefix (e.g. a robot emoji) so people know it is automatic.
5. The existing "Read notifications with AI" reader is unchanged: still on-demand, no history.

Honest limits
- Unofficial method: it works only while WhatsApp shows a message notification with a Reply button. Muted or cleared chats, hidden-content lock-screen settings and force-stopped apps cannot be answered. Replies go out as YOU. Media shows only as "Photo" / "Voice message".
- WhatsApp could change its notifications; Android may stop the listener under aggressive battery saving (Horizon asks for the battery exemption when you switch on).
- Horizon lock does not gate replies (otherwise nothing could answer while the app is locked); it does gate the log screen.
- NOT checked: no APK build, no Kotlin compile (no toolchain here), no device run, no real WhatsApp message. Checked: tests/wabot-v137.test.cjs (static checks of the Kotlin wiring and safety gates, the JS module in a mock), the full suite.
