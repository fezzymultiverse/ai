HORIZON V1.99.135 - HORIZON EYES (REAL VISION FOR EVERY CHAT MODEL)

Problem: only Gemini (and a few Mistral/Cohere/OpenRouter/Pollinations models) could really see pictures. ch.at, Groq and most free text models got a note saying "cannot see images".

What it does
- When the chat model cannot see pictures, the app sends each picture (attachments, scanned PDF pages, Lens screenshots) to a vision-capable provider the user already has: Gemini, Mistral Pixtral, OpenRouter vision models, Cohere vision, or keyless Pollinations, tried in that order, 45 s each, skipping the chat provider and switched-off providers.
- The vision model is asked to describe it literally: what it is, ALL visible text transcribed, layout, objects, people (described, never identified), UI elements, errors, numbers, what is unclear. It is also told what the user asked, so the description targets the question.
- The description goes to the chat model as text, labelled with who read it, with the instruction that it cannot see the picture itself, must rely only on the description and must not invent details. This is the anti-hallucination guard.
- The same picture is described once (40-entry cache for the session). The chat shows "Reading the picture with a vision model" then "Picture read by <provider>" in the thinking steps.
- Send-time notice now says which provider will read it; it only shows an error when no vision provider is ready.
- Off switch: localStorage horizon_eyes = '0'.

Not done: the chat model cannot ask follow-up questions about the picture mid-reply (a see.ask tool); a follow-up in a later message re-uses the cached description. Real pixel access for text-only models does not exist; this is vision-by-description.
