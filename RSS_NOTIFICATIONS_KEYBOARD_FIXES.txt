HORIZON RSS / NOTIFICATIONS / KEYBOARD PATCH

Scope: RSS fetching/discovery, opt-in Kotlin notification reading, and focused keyboard/loading cleanup. Existing app identity/version, chats, keys, Vault, audio, layouts and unrelated features are retained. The layout cleanup removes redundant overridden declarations; it is not a redesign.

RSS
- Explicit CapacitorHttp native GET on Android for all HTTP(S) feed domains; the AI endpoint allowlist is not used. No public CORS proxy added.
- Search combines GitHub, YouTube, Reddit and independent website directories (Feedly and WordPress). Candidate feeds are checked, not invented.
- RSS 2.0, RDF/RSS 1.0, Atom, JSON Feed 1/1.1 and relative article URLs supported.
- A broken advertised alternate no longer rejects valid alternates. An HTML page returned with HTTP 200 at /feed no longer aborts the remaining probe paths. Also probes directory-local feeds.
- At most 3 logical requests at once; native connection/read timeouts, overall JS deadlines, body-size validation, safe-link validation and cached feeds remain.
- Limitations: no reader can extract an RSS feed from every website. Sites without feeds, authentication requirements, blocks, rate limits and outages remain real constraints. Browser preview remains subject to CORS; test cross-origin feeds in the Android build.

NOTIFICATIONS: ENABLE AFTER REBUILD
1. Rebuild using the project's existing Android/GitHub Actions workflow. Copying only www files does not install Kotlin plugins.
2. Open Settings > Permissions > Read notifications with AI.
3. Read the disclosure and choose Agree and continue, then allow Horizon in Android Notification access and return to the app.
4. Send a private AI chat message. Horizon reads an on-demand snapshot of active notification titles/text exposed by Android and shares it with the selected provider. There is no polling and no stored notification history.
5. Turn that permission row off to stop AI sharing immediately. To revoke device-level access too, switch Horizon off in Android Notification access settings.

The existing permission to post notifications is separate and is labelled accordingly. Both Android listener permission and the explicit AI-sharing preference must be enabled before a read. The default is off. People chats are excluded. Notification text is untrusted data, not instructions. Snapshots are cleared on turn completion, disabling, app backgrounding/resume and cancellation; delayed reads cannot restore cancelled snapshots.

This is access to current active notifications, NOT all historical notifications or all messages inside other apps. Android may redact sensitive/OTP content or exclude work-profile data. Very long notification bodies and AI context are bounded, with truncation labelled. No notification text is written to local storage, a database, or logs by this reader. If the AI repeats notification content in a reply, the existing chat history may of course retain that reply.

KEYBOARD / LOADING
- Expensive lag-diagnostic PerformanceObservers now start only when /lag is explicitly opened, and disconnect when it closes.
- Backspace textarea collapse/read/expand is debounced instead of repeated for every deletion; IME composition protection and native keyboard settling remain.
- Reply-fold height measurements defer during typing/keyboard motion and do not measure detached replies.
- Media status polling skips work while an editor/keyboard is active. Playback engines are unchanged.
- Removed replaced duplicate Browser/Group header nodes after the current header is successfully installed, redundant unconditional layout declarations, and verified dead local variables. Hidden bridge elements that are still referenced are intentionally kept.
- Scoped asset cache busting prevents stale changed scripts/styles. No dependency additions or global fetch override.
