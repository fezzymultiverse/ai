HORIZON V1.89.0 — ROBUST PERFORMANCE PLAN

PHASE 1 — IMPLEMENTED IN THIS SOURCE
Single layout/stylesheet owner, cache-versioned resources, obsolete shell removal,
lazy terminal settings, one command bridge, batched output, bounded history,
event-based AI terminal mounting, no idle laser interval, background/reduced-motion
animation pause, existing offscreen message content-visibility retained.

PHASE 2 — REAL-PHONE ACCEPTANCE BEFORE CALLING THIS A VERIFIED ANDROID RELEASE
1. Build/sign the APK with the existing GitHub workflow; verify V1.89.0 in About.
2. Back up through the app, then update over V1.87.1 with the same signing key.
   Preserve data. Force-stop/reopen, rotate and background/resume. Confirm the new
   layout appears every time and chats, providers, Vault and audio settings survive.
3. On a mid-range/low-memory phone, record 10 cold starts and 20 warm resumes.
   Separate local UI startup from network/model time. Compare medians AND p95,
   WebView long tasks, memory/PSS, input delay and scroll frame drops.
4. Run the existing /lag panel during typing, a 300-message chat, Settings scrolling,
   music playback and a large terminal output. Do not run decoration at the cost of
   typing, keyboard geometry or audio continuity.
5. Verify real Termux setup + printf, cd/pwd, stderr, nonzero exit, permission denial,
   declined approval, a long-running job, timeout, late callback, app process death,
   job recovery and explicit retry. Confirm no duplicate command submission occurs.
6. Test one permitted music/audio download and one ordinary file download. Check the
   actual saved file and path, not only a queued status. Check shared storage denied
   and fallback storage, offline conditions and unavailable extractors.
7. Test WhatsApp Personal and Business separately; notification access denied/granted,
   inbox clear, exact recipient selection, cancelled reply and confirmed submission.
   Submission is not proof of delivery. Keep device permission controls in Permissions.
8. Test the paste box with real keys only on the owner's device. Check mixed providers,
   duplicate keys, intentionally wrong labels, denied replacement, 401/403/429/500,
   network failure, partial success, backup-key preservation and private screen capture.

PROPOSED ACCEPTANCE TARGETS — NOT CLAIMED ACHIEVED
- No regression in data preservation, permissions or keyboard focus.
- p95 key handling under 50ms during normal chat; no recurring idle 300ms laser work.
- No major scroll jank while audio runs; aim for under 5% dropped frames in a controlled
  60Hz scroll test on the selected test phone.
- Zero missing bundled assets, duplicated live IDs or alternate old layout paths.
- One logical Termux command flow with explicit unknown/cancelled/failed distinctions.
- Lower median cold-start UI time than the old APK on the SAME phone and conditions.

PHASE 3 — ONLY AFTER A DEVICE PROFILE IDENTIFIES THE REMAINING BOTTLENECK
- If JS parse/startup dominates, split heavyweight extensions behind first-use loaders
  with a single-flight loader and dependency tests; preserve each existing global API.
- If long chat rendering dominates, incrementally render older messages without breaking
  search, quote/swipe, read-aloud position, selection, exports or hardware Back.
- If storage serialisation dominates, debounce writes and measure IndexedDB migration
  with verified rollback; do not wipe localStorage or move secrets without a backup.
- If music scans or voice setup dominate, run them only on demand and deduplicate native
  jobs. Preserve foreground services and background audio ownership.
- If provider responses dominate, show accurate tool/provider timing; do not hide it with
  a false UI speed claim or silently route a private message to a different provider.
