HORIZON V1.99.138 - YOUTUBE LIST IN THE CHAT, FAST THINKING, SAFE DELETE, TIDY FILE PLANS

Asked for: a YouTube interface that pops up in the chat (scroll, tap to download, ask the AI to play, or paste a link and play, and the AI must know download from play); AI thinking too long; Gemini out; Groq/DeepSeek speed for file manager moves; the black plan display made presentable; deletes only with permission and confirmation.

IMPLEMENTED
1. YOUTUBE LIST IN THE CHAT (www/horizon_ytpick.js, new). The AI opens it with [[yt.pick: words]]. A scrollable card appears inside the chat: picture, title, artist, length, and four buttons per row: Play (streams, saves nothing), Audio and Video (save to the phone, with a progress bar on the row and a "Saved" state), Link (copies the youtube.com link). A paste box at the top takes any YouTube link or video id: play it or save its audio. Nothing plays or saves until a button is tapped. The prompt tells the AI the difference: DOWNLOAD saves a file, PLAY only streams, and after yt.pick it must say one short sentence and not retype the list. The last 8 cards per chat are remembered (ids and titles only) and come back after the message they were made for when the chat is reopened.
2. SPEED. Thinking is now OFF until switched on (it was ON by default, with Gemini allowed up to 24576 / 32768 thinking tokens). When on, Gemini 2.5 is capped at 2048 (Flash) / 4096 (Pro), Gemini 3 at level low. With Thinking off, Gemini 2.5 Flash is sent thinkingBudget 0 so it answers at once. On Groq, gpt-oss models get reasoning_effort low (medium when Thinking is on) and qwen3 gets none when Thinking is off. The file manager prompt now says: do not think at length, inspect once, send one plan.
3. GEMINI OUT OF EYES. Gemini is no longer a picture reader for Horizon Eyes (it was first in the order). Order is now Groq vision, Mistral, OpenRouter, Cohere, Pollinations. Gemini is still a chat provider and still the song-listening (ears) tool; nothing else was removed.
4. FILE PLAN CARD, PRESENTABLE. Header with the change count and coloured chips (new folder, move, rename, delete), file name first with a coloured action badge, short folder names, first 6 rows with "Show all N", a progress bar, green/amber/red outcomes, and a tidy summary after ("7 of 8 changes done, 1 moved to Trash, 1 kept").
5. DELETE ONLY WITH YOUR PERMISSION. The AI may propose moveToTrash in a plan. Apply becomes "Apply..." and opens a confirmation panel listing every delete with an UNTICKED tick box; only ticked items go to Trash, the rest are kept. Items go to Documents/Trash (a rename, journaled, Undo in File activity). Permanent delete does not exist anywhere. The app sets userConfirmed only after the panel; the Java plugin refuses moveToTrash without it.

NOT CHECKED
- No APK build, no Kotlin/Java compile (no toolchain here), no device run. The Java moveToTrash body reuses the existing transfer() trash path but has never been compiled or run.
- Real YouTube search/play/save was not run (no network here). The card, buttons, progress, paste box and restore were tested in real Chromium with a MOCKED host; yt.pick's own search call uses the existing ytSearch.
- Speed was not measured. The reasoning_effort values follow Groq's documented gpt-oss / qwen3 options and are sent only to those models. DeepSeek was left alone: no reasoning field is sent because an unsupported field would fail the request. Pick a DeepSeek non-reasoning model or leave Thinking off for speed.
- It lists search results (videos). It does not open a YouTube playlist page and read its tracks.
